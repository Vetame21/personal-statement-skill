# Humanizer benchmark

A small, open benchmark: does a humanizer keep the facts, avoid inventing details, and remove the template feel? It does **not** measure AI-detector scores. Optimising for those is what these skills refuse to do, and detectors are unreliable anyway.

Results: [RESULTS.md](RESULTS.md) (generated by `score.py`).

## Samples (all fictional)

| File | What it is |
|---|---|
| `samples/gpt_essay.txt` | A "Harvard" personal statement written by ChatGPT on request (November 2026). It has no old-style AI words, but a lot of template structure. |
| `samples/student_statement.txt` | A school leaver's statement with AI-style padding, an unchecked ranking claim, pleading and a placeholder. |
| `samples/ai_paragraph.txt` | A short, deliberately AI-sounding paragraph with no concrete facts. |

`samples/facts.json` lists the facts each output must keep.

## The task (the same for every tool)

> Humanize this text so it sounds natural and like a real person wrote it. Keep every fact. It is my own draft and AI editing is allowed. Humanize only; don't add new content.

Each condition ran in a **fresh agent** that had not seen the scoring, the other outputs or this page. If the tool asked a question, the agent answered it from the task above. Only the final text was saved.

## Conditions (November 2026)

| Folder | Condition | Model |
|---|---|---|
| `outputs/baseline` | The task as a plain prompt, no skill | Claude (Claude Code subagent) |
| `outputs/vetame` | The task with this repository's `humanizer` skill | Claude (Claude Code subagent) |

**Not run yet:** [blader/humanizer](https://github.com/blader/humanizer) (MIT, the most-starred open-source humanizer skill we found) and commercial humanizer websites. Our session's permissions did not allow an agent to follow a downloaded third-party skill. To add one, run the task above with that tool and save the outputs in `outputs/<tool-name>/` (one file per sample, same file names). Then run `python3 bench/score.py`. Pull requests with outputs are welcome.

## Metrics

| Metric | What it means | Who it favours |
|---|---|---|
| **Facts kept** | Share of the facts in `facts.json` still present | Neutral |
| **New specifics** | Numbers and capitalised names in the output that are not in the input. These are possible inventions, so check them by hand. | Neutral |
| **Flags in → out** | `humanize_check.py` total flags: AI-typical words, padding, template structure and so on | **Favours this repository**, whose humanizer is told to run this checker |
| **Template in → out** | Template-structure signals: punchline paragraphs, stock reflection, contrast template, closing moral | **Favours this repository**, same reason |
| **Words in → out** | Length change. Humanize-only should stay within about ±10%. | Neutral |

## Limits (read before quoting any number)

- **Tiny:** 3 samples, 1 run per condition. Results can change from run to run.
- **One model family:** every output so far is from Claude. A different model may do better or worse with the same skill.
- **Home advantage:** two of the five metrics use this repository's own checker.
- **No human rating yet.** The most important question, "which version sounds more like a real student and keeps the meaning?", needs blind ratings by people. Add yours in an issue.
- The fact check is pattern-based: a fact reworded in a different way can count as missing. Missing items are listed so you can check them.

## Run it

```bash
python3 bench/score.py
```

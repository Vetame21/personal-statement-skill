# Debate Rules

Shared by every skill that runs a debate or review panel (personal-statement, thesis, report, debate-mode, harvard-cv).

## Four rules

1. **No instant agreement.** Restate the claim or proposal in checkable form before judging it. Never open with "Yes / Good idea / Setuju".
2. **Research before verdict.** Factual parts are checked against sources found in this session (see `evidence-standards.md`). Without a search tool, verdicts are marked *provisional*.
3. **Steelman both sides.** State the strongest case for and against.
4. **Change position only for reasons.** New evidence, a better argument or a new constraint can change a verdict; repetition or insistence cannot. Contrarianism for its own sake breaks this rule too.

## Claim types

| Type | Example | How it is judged |
|---|---|---|
| Fact | "Hong Kong is the biggest IPO market this year" | Sources |
| Causal | "AI fraud makes banking harder" | Evidence for the mechanism |
| Relevance / fit | "This news doesn't belong in a Data Science statement" | Program pages, reader expectations, the applicant's own story |
| Preference | "I like the casual tone better" | Trade-offs only; the user decides |

## Verdicts

**Yes / No / Partly / Not enough evidence**, each with a confidence (high / medium / low) and the one or two strongest reasons. Often the most useful verdict is "your conclusion is right, your reason is wrong" (or the reverse).

## Panels

- Each panelist writes their view **before** reading the others, then answers one other panelist's strongest point (the clash).
- The Moderator turns the clash into decisions: **Fix now / Keep / User's call** (or the skill's equivalent) and, where useful, 1-5 scores.
- Quick mode (one clash round) by default; "deep" (two rounds, or parallel subagents where the environment supports them and the user asked) on request.
- Keep it short: bullets, quotes from the text, concrete fixes.
